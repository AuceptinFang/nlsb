# 规则识别器

`nlsb` 默认用的是[分类器](model.md)；这个规则识别器是备选（`NLSB_DETECTOR=rules`），适合不想下载模型的场合，代价是误伤多得多。

不使用任何模型：全部是手写的图像特征，加上一组可读的加减分规则。没有神经网络，也没有训练出来的权重文件。
所有权重和阈值都在 `src/nailong/score.py`，每一项都有注释。

## 特征

特征都在缩放后的图上计算：颜色、形状、纹理用长边 128px 的图，眼睛用长边 256px 的图。

**眼睛（最强的线索）**

奶龙的眼睛是"黑瞳孔，外面一圈绿虹膜，再外面是黄皮肤"。检测方法是中心-环绕滤波：

- 对每个候选点、每个尺度 r，计算三个同心方框里各种颜色的占比：
  - 核心要黑；
  - 中间一圈要绿；
  - 最外圈要黄，而且不能还是绿（用来排除草地背景）。
- 方框和用积分图在 O(1) 时间内取得。四个颜色通道各占 16 位，打包进一个 uint64，一次 `cumsum` 就得到全部积分图。
  方框和是线性运算，在 mod 2⁶⁴ 下依然成立；每一段的计数都小于 2¹⁶，所以能无损拆开。
- 只在深色像素上求值，因为瞳孔中心必然是深色的。深色像素通常只占画面的百分之几。
- 同一套滤波还会给出另外两个信号：
  - 瞳孔里有没有高光（3D 渲染的大黑眼睛会有）；
  - 眼睛周围是黄皮肤，还是白色眼白（emoji 是后者）。

**其他线索**

| 线索 | 奶龙 | 典型干扰项 |
|---|---|---|
| 奶油黄像素的占比、色相 | 偏暖的奶油黄 | 小黄脸 emoji 更橙、更艳 |
| 硬边密度 | 3D 渲染，几乎没有硬边 | 线条画、动漫、emoji 描边 |
| 黄色区域的细纹理（128px 和 256px 各算一次） | 光滑的塑料感 | 毛发、照片噪点 |
| 外接框长宽比 | 竖长的团子 | 正圆的 emoji 脸 |
| 红色、深色描边 | 很少 | emoji 的舌头、腮红、描边 |
| 橙色皮肤，以及被皮肤包围的深红色嘴 | 橙色大笑版 | — |
| 大尺度光影相对小尺度残差的比例 | 高 | 平涂 |

**两条特例**

- **颜色门槛的眼睛特例**：奶油黄不足 15% 本来直接判否。但如果黄加橙不低于 10%，并且有一对强绿眼，就照常打分。
  这是为了奶龙头 P 在照片上、画面里黄色很少的情况。
- **强绿眼对加分**：用来抵消描边、硬边、眼白这些针对 emoji 的扣分。
  平面卡通版、"奶思"花形头像一类的衍生形象，会同时触发这些扣分。

每条线索满足就加分或扣分，总分过阈值就判为奶龙。

## 准确度

数据来源：一个人 QQ 缓存里的 6161 张去重表情，人工标注了 886 张，其中奶龙 256 张。
数据按 md5 固定切成 tune、val、test 三份。tune 用来搜参数，val 用来挑参数和看错例，test 只用来报告。

| 预设 | tune 精确率 / 召回率 | val 精确率 / 召回率 | test 精确率 / 召回率 |
|---|---|---|---|
| `aggressive` | 73.2% / 94.6% | 72.1% / 93.9% | **67.8% / 98.3%** |
| `balanced` | 88.5% / 83.1% | 91.7% / 83.3% | **80.7% / 76.7%** |

读这张表时请注意：

- 数据量很小，test 只有 60 张奶龙，数字的波动大约在 ±5 个百分点。
- test 一共被看过三次：第一次是最终评估，后面两次是规则更新后重新报告。决定这些更新的错例都来自 val 和实际使用，没有来自 test。
- 标注集偏向"黄色的图"：黄色候选全部标注，其余只是随机抽样。在真实分布上，误判率会更低，因为绝大多数表情根本过不了颜色门槛。
- 标注由一个人看图完成，"什么算奶龙衍生"有主观成分，已经发现并改正过 6 个标错的样本。
- **已知的短板**：
  - 认不出：黑白或严重偏色的奶龙，很小、很暗的奶龙。
  - 会误判：黄色毛绒玩偶、长得像 emoji 的黄色 3D 角色，以及个别橘猫、黄狗的照片。

## 性能

| 实现 | 机器 | 吞吐 |
|---|---|---|
| Python（`nailong.detect`），单核 | Apple M4 | 约 2 ms/张（真实表情分布，不含读盘） |
| Python，单进程 | Intel Core Ultra 7 155H | 145–152 张/秒（8921 张、4 GB 的 QQ 缓存，包括大照片，含读盘） |
| C（`native/`），1 线程 | 同上 | 446–460 张/秒（约 3 倍） |
| C，22 线程 | 同上 | 3300–3390 张/秒（约 22 倍）；连续满载、散热饱和后约 2500 张/秒 |
| GPU 后端（wgpu）+ 8 线程预处理 | 同上（Intel Arc，Vulkan） | 约 860 张/秒 |

Python 版做过的优化，以及它们对结果的影响：

| 优化 | 对结果的影响 |
|---|---|
| 只在深色像素上计算眼睛特征 | 逐位不变 |
| 四个通道打包成 uint64，一次 cumsum 出全部积分图 | 逐位不变 |
| 不补边，把越界坐标裁剪到边界（等价于补零） | 逐位不变 |
| 黄色加橙色不足 `gate_lo` 的图提前退出 | 判定不变（分数恒为 -10） |
| 不透明图跳过 alpha 合成；先整数倍 reduce，再精确缩放 | 逐位不变 |
| JPEG 直接按目标尺寸做 DCT 域缩放解码 | 准确度不变 |
| 瞳孔候选点按棋盘格隔一个取一个 | aggressive 在 val 上不变 |
| 128px 小图改用 2 倍盒式降采样 | 召回下降，**默认关闭**（`features.FAST_SMALL`） |

## native：C 实现，与 Python 逐位一致

`native/` 是整条流水线的 C 实现，编译成共享库，内部用线程池运行。它的定位是对大量图片做批量扫描：

- **解码**：JPEG 用 libjpeg-turbo，加上自己写的哈夫曼解码；PNG 用 libdeflate 一次性解压，SIMD 反滤波；GIF 用自己写的第一帧 LZW 解码；WebP 用 libwebp。
- **缩放和 HSV 转换**：按 Pillow 13 的定点算法逐条复刻，用 AVX2 和 VNNI 加速。HSV 对全部 2²⁴ 种颜色做过穷举验证。
- **特征和评分**：复刻 numpy 的语义，包括 float32 成对求和、分位数插值、NEP 50 下的比较规则。

在 8921 张真实图片上，20 个特征和两档分数全部与 Python 参考实现逐位相同。少见的格式会回退到 Python，例如 CMYK JPEG、16 位灰度 PNG。

使用条件和注意事项：

- 只支持 Linux x86-64（需要 AVX2），并且必须在运行它的机器上编译。
- 需要 libjpeg-turbo 3.2.x（含 `jpegint.h` 头文件）、libdeflate 和 libwebp。
- JPEG 的快速路径依赖 libjpeg-turbo 的内部结构。升级这个库之后，请重新跑 `native/verify.py`。
  设置 `NL_JPEG_NOFAST=1` 可以关掉快速路径。

```bash
cd native && make
python test_synth.py                      # 合成图端到端校验
python verify.py 图片列表.txt --threads 1,8,16   # 用你自己的图校验逐位一致，并计时
```

## GPU 后端（`pip install ".[gpu]"`）

GPU 后端基于 wgpu：Linux 和 Windows 上走 Vulkan 或 D3D12，macOS 上走 Metal。只有眼睛检测交给 GPU 批量计算，结果与 CPU 逐位一致：

- GPU 上不做浮点除法，掩码、积分图、方框计数都是整数。
- 阈值判断改写成交叉相乘，例如 `core_d ≥ 0.55` 写成 `20·cd ≥ 11·a1`。
- 每个尺度的分母是固定的，所以"比例的最大值"等于"分子的最大值"，可以用整数原子操作求出，最后在 CPU 上做一次除法。

实测下来，这个任务的瓶颈是解码，GPU 帮助有限。批量处理时，`native/` 的多线程 C 实现快得多。

## 用自己的数据调参

```bash
python tools/tune.py labels.csv [--beta 2] [--restarts 40] [--final]
```

`labels.csv` 的列是 `path,label,split`：label 中 1 表示奶龙、0 表示其他；split 取 tune、val 或 test。

- 在 tune 上做坐标下降，多次随机重启，再在 val 上挑出最好的一组，结果写到同目录的 `params.json`。
- `--beta 2` 优化 F2，偏向召回。
- 只有加 `--final` 才会评估 test。
- 得到的参数可以直接传给 `nailong.detect(..., params=...)`。

**注意**：用 `nlsb` 屏蔽过的表情，缓存里已经是占位图了。评估时请改用 `backup/` 里的原图，否则结果会失真。
