# 分类器：DINOv2-small + 逻辑回归

`nlsb` 默认用的识别器。规则识别器（[algorithm.md](algorithm.md)）不需要模型，但误伤太多：
它只能看颜色和"绿圈黑瞳"这类局部特征，分不清奶龙和其他黄色圆脸角色。
真人穿的奶龙玩偶服、夜里拍的照片这类颜色不纯的图，它也会漏掉。

## 结构

1. **骨干网络**：[DINOv2-small](https://github.com/facebookresearch/dinov2)（Meta，Apache-2.0，2200 万参数），
   用 [Xenova/dinov2-small](https://huggingface.co/Xenova/dinov2-small) 导出的 int8 量化 ONNX，24 MB。
   fp32 版（88 MB）在同一批数据上准确度没有差别（fp32 召回 93.3%、误判 38.8 张；int8 召回 93.8%、误判 40.4 张，都在随机波动范围内），但多占约 100 MB 内存。
   它是自监督预训练的通用视觉特征，没有针对奶龙训练过，也不需要微调。
2. **预处理**：大图先缩小（JPEG 解码时按 1/2、1/4、1/8 缩，其他格式整数倍缩到长边 512～1024），透明处垫白，白边补成正方形（不裁掉边缘），双三次缩放到 224×224，ImageNet 均值方差归一化。
3. **特征**：CLS token 和所有 patch token 的平均值拼成 768 维，再做 L2 归一化。
4. **分类头**：L2 正则的逻辑回归（λ=30，牛顿法求解）。只有 768 个权重加一个截距，存在 `src/nailong/head.npz`（4 KB）。
5. **动图**：取 4 个均匀分布的帧分别打分，取最高分。分数 ≥ 0.5 判为奶龙。
6. **拼图**：整图没命中时，把拼图切成子图（`src/nailong/collage.py`），每块单独打分，至少两块 ≥ 0.8 才算命中。

训练时每张图用了 5 个样本：首帧、首帧的水平翻转，以及动图的另外 3 帧。

### 拼图

一张 4×4 的奶龙表情合集缩到 224×224 后，每只只剩 40 px 左右，整图分数接近 0。切开分别打分就认得出。

切法借鉴漫画分格工具 [Kumiko](https://github.com/njean42/kumiko)（只借思路，没有用它的代码）：

1. 在长边 384 px 的缩略图上，找纯色背景上的连通区域，丢掉短边不到整图短边 12% 的（文字、标签、图标），合并互相重叠的框。
2. 每个框里再递归找分隔带切开，要求切开后每块都不小于上面那个尺寸：
   - 背景色的空带，允许夹着 20% 以内的前景。格子之间的说明文字会把上下两格连成一个连通区域，这样能切开；
   - 一到三行颜色均匀的细线。图框贴着图框时（比如 matplotlib 画的对比图），中间只剩一条框线。
     图片里大片的纯色（天空、墙）是很多行连成一片，不会被当成分隔线。
3. 高宽比 ≥ 2 的竖图不切：几乎都是手机截图。

几个取舍：

- **不用固定网格切**：黄色角色的局部放大后很容易被认成奶龙。试过 2×2～4×4 网格切块，白名单（人工放出过的难负样本，659 张）的误判从 3 张涨到 68～214 张。
  沿空隙和框线切出来的是完整的画面，和训练数据同分布。
- **要两块同时命中**：截图里夹着一张奶龙表情很常见（聊天、帖子截图），这类图只有一块高分，用户之前也把它们放出了，所以不算。
- **竖长截图不切**：聊天记录、表情搜索结果、商品页里常常一连好几张奶龙表情，能切出好几块高分。白名单里有 3 张这样的图，说明用户不想整张屏蔽。
- 第一版只按整行整列的空白切（XY-cut），格子间有字、图框相贴的拼图都切不开。

在 2 万张缓存上（阈值 0.8）：

| | 只按空白切 | 现在 |
|---|---|---|
| 白名单 659 张误判 | 0 | 0 |
| 其他图片约 2 万张，新增命中 | 2 | 3 |

现在的 3 张里，2 张是"高校流动奶蛙汇总"（4×4 的奶蛙照片合集，本来就该拦），1 张是三个黄色团子头像（误判）。
另外有一张 2×6 的"Base SD1.5 vs 奶龙 LoRA"对比图，只按空白切时没能切开，现在能识别。

- 只对第一帧做。切分本身在缩略图上做，每张 10 ms 左右；能切开的图要多做最多 16 次推理（每次约 50 ms），够两块命中就停。

## 准确度

数据：一个人 QQ 缓存里的 3556 张图，其中奶龙 410 张（换了颜色的奶龙、玩偶服、真人照片里的奶龙也算）。负样本分两类：

- **难负样本** 1147 张：规则识别器和早期分类器误判过的图，大多是黄色的圆脸角色；
- **随机表情** 1999 张：从缓存里随机抽的、从没被判成奶龙的表情和聊天图片（风景照、截图、人像等）。

第一版只用了难负样本，结果在风景照和聊天截图上大量误判：扫描 1.8 万张缓存，命中的 197 张里约 80 张是这类图。
加入随机表情之后才解决。下面是 5 折交叉验证的结果（5 个随机种子取平均，λ=30）：

| 阈值 | 漏判（共 410） | 难负样本误判（共 1147） | 随机表情误判（共 1999） |
|---|---|---|---|
| **0.5（默认）** | 26（召回率 93.8%） | 39 | **1.6** |
| 0.7 | 40（召回率 90.3%） | 26 | 0.6 |

日常收到的表情绝大多数属于"随机表情"那一类，误判率约 0.06%；实际扫描 1.8 万张缓存时误判了 8 张（0.04%）。容易出错的是长得像奶龙的黄色角色。

对比：在最早那批 1378 张图（随机表情之外的部分）上，规则识别器 `aggressive` 的精确率是 38.4%，召回率 95.7%，误判 495 张。
分类器在同一批图上的误判是 25 张左右。

剩下的错误大多是边界情况，人工标注本身也不一致：比如同一张图的两份缓存被标成了相反的标签；
一些带橙色呆毛的黄色角色有时标成奶龙，有时不标。再往上提，主要得靠更一致的标注，换更大的模型帮助不大。

## 运行成本

见 README 的[运行成本](../README.md#运行成本)。

分类器跑在一个按需启动的子进程里：加载后约占 120 MB 内存（Python 和各个库 42 MB，int8 模型 74 MB），
解码图片又会留下几十到上百 MB 的堆碎片，这些都不会还给系统。所以子进程空闲 5 秒就退出（重新启动只要 0.15 秒）、每识别 20 张就换一个新的，
常驻的主进程不加载 numpy 和 onnxruntime。

## 用自己的数据重新训练分类头

```bash
python tools/train_head.py labels.csv       # 列: path,label   label: 1=奶龙 0=其他
```

会打印 5 折交叉验证的精确率和召回率，并把全部数据训练出的分类头写回 `src/nailong/head.npz`。
特征缓存在 `labels.emb.npz`，以后加新图只需计算新增的部分。
