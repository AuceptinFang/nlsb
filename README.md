# nlsb QQ

nlsb (nai long sticker blocker) 用于**自动识别并屏蔽QQ中收到的奶龙**（包括各种乱七八糟的衍生形象）仅保证macOS 使用，linux 未充分测试，windows 用户请自行适配

几点说明：

- **仅修改设备上的缓存文件，不介入客户端，无封号风险**：只改写你自己电脑上的缓存文件。原图默认会先备份（可配置）。
- 由于篡改的是本地缓存，因而已加载出的图片需要刷新后才能屏蔽
- **识别用一个小模型**：DINOv2-small 提取图像特征，加一个只有 768 个权重的逻辑回归。原理见 [docs/model.md](docs/model.md)。
  另有一个不用模型的规则识别器可选，但误伤多得多（[docs/algorithm.md](docs/algorithm.md)）。
- **常驻成本低**：空闲时几乎不占 CPU，主进程内存 15–35 MB；模型只在有新表情要识别时才加载，空闲 5 秒就释放。具体数字见下文的[运行成本](#运行成本)。
- 只在本地运行。唯一的联网是第一次运行时从 Hugging Face 下载模型（24 MB）。

## 安装

需要 Python 3.9 或更高版本，支持 macOS 和 Linux 上的 QQ（NT 版）。

```bash
python3 -m venv ~/.nlsb && ~/.nlsb/bin/pip install .
~/.nlsb/bin/nlsb install
```

`nlsb install` 会下载模型（24 MB），装好后台服务（macOS 用 launchd，Linux 用 systemd --user），开机自动运行。
之后新收到的奶龙会自动屏蔽；已有的缓存会在后台空闲时慢慢扫一遍，不用管。
macOS 第一次运行时可能弹窗问"是否允许访问其他 App 的数据"，选允许。

下载慢的话，可以先设 `HF_ENDPOINT=https://hf-mirror.com` 再运行 `nlsb install`。

## 用法

一共 4 个命令：

```bash
nlsb                          # 查看状态：服务是否在运行、屏蔽了多少、最近屏蔽了哪些
nlsb block   <表情>…          # 屏蔽指定的表情
nlsb unblock <表情>…          # 放出（比如被误伤的），以后也不会再自动屏蔽它
nlsb install [--no-backup]    # 安装或更新后台服务；--no-backup：屏蔽时不备份原图
nlsb uninstall [--restore]    # 卸载后台服务；--restore：同时还原所有已屏蔽的表情
```

**表情**：在 QQ 里对表情右键「另存为」，把得到的文件名（形如 `0123456789abcdef0123456789abcdef.jpg`）或者整个路径给 `nlsb` 就行。
屏蔽和放出之后，重新打开聊天窗口就能看到效果。

**备份**：默认屏蔽前先备份原图，放出时直接写回。用 `--no-backup` 可以省磁盘，代价是放出时只能删掉占位图，等 QQ 重新下载。
想改的话，带上或去掉 `--no-backup` 重新运行一次 `nlsb install` 即可。

**卸载**：`nlsb uninstall` 只停掉服务，已屏蔽的表情仍是占位图；加 `--restore` 会把它们全部还原。
名单、备份和日志都在数据目录里（macOS `~/Library/Application Support/qq-sticker-block`，Linux `~/.local/share/qq-sticker-block`），不需要了可以整个删掉。

## 工作原理

1. QQ 收到的表情会按 MD5 存成缓存文件，路径形如 `nt_data/Emoji/emoji-recv/<年-月>/Ori/<md5>.jpg`。
   同一个表情再出现时，QQ 直接读这个本地文件，不校验文件内容。
2. `nlsb` 把黑名单里表情的缓存文件原地替换成占位图，原图先备份到数据目录。对手动屏蔽的表情，还会提前放好各种扩展名的占位文件。
3. 后台服务监听缓存目录，完全由事件驱动：macOS 用 kqueue，Linux 用 inotify。
   - 新文件一落地就交给识别子进程打分。命中就加入黑名单，并立刻替换。
   - 识别子进程按需启动，空闲 5 秒退出。这样平时不占模型那 170 MB 内存。
   - 已屏蔽的文件被 QQ 改回原图或重新下载时，也会立刻被换回占位图。

## 运行成本

以下数字在 Apple M4、macOS 上的 QQ 7.0.1 实测，黑名单 436 项。

| 项目 | 数值 |
|---|---|
| 空闲 CPU | 每 60 秒约 0.02 秒，每 30 秒醒一次 |
| 主进程内存 | 15–35 MB（不加载 numpy 和模型） |
| 识别子进程 | 只在有新表情时启动（0.15 秒），空闲 5 秒退出；运行时 170–210 MB |
| 识别一张新表情 | 中位 57 ms，动图和大图 P90 约 170 ms（2 线程） |
| 从收到新表情到被替换 | 0.3–0.5 秒，外加冷启动约 0.3 秒（距上一张超过 5 秒时） |
| 文件句柄 | 每个已屏蔽的文件 1 个（436 项时约 1200 个） |
| 磁盘 | 模型 24 MB（int8）；原图备份约等于被屏蔽表情原图的总大小（436 项共 384 MB，`NLSB_BACKUP=0` 可关掉）；每个占位图约 3 KB |
| 首次安装后扫描已有缓存 | 只在空闲时做，每 0.2 秒一张；1.8 万张约 1 小时，只做一次 |

子进程用完就退出，是因为 ONNX Runtime 和图片解码占用的内存不会还给系统：常驻的话会一直占着几百 MB。
它每识别 20 张也会换一个新的，避免内存越涨越高。

用规则识别器（调试用，`NLSB_DETECTOR=rules`）的话不需要模型：常驻内存约 42 MB，识别一张约 2 ms，但误伤多得多（见下表）。
`native/` 里还有规则识别器的多线程 C 实现，结果与 Python 版逐位一致，在 22 线程的 Linux 机器上每秒约 3300 张。

## 识别准确度

数据来源：基于本人 QQ 缓存里的图，人工标注 3556 张，其中奶龙 410 张。
负样本里有 1147 张是长得像奶龙的黄色角色（难负样本），1999 张是随机抽的普通表情和聊天图片。5 折交叉验证：

| 识别器 | 召回率 | 难负样本误判 | 普通表情误判 |
|---|---|---|---|
| 分类器（默认，阈值 0.5） | 93.8% | 39 / 1147 | **约 1.6 / 2000** |
| 分类器（阈值 0.7） | 90.3% | 26 / 1147 | 约 1 / 3000 |
| 规则 `aggressive` | 95.7% | 495 / 1055（另一批，见 [docs/model.md](docs/model.md)） | — |

实际扫描 1.8 万张缓存时，分类器误判了 8 张普通图片（约 0.04%）。
误伤的表情用 `nlsb unblock` 还原就行，还原后不会再被自动屏蔽。

## 已知的限制和风险

- **依赖 QQ 的缓存行为**。在 macOS QQ 7.0.1（App Store 版）上实测过：QQ 会直接显示本地缓存里的占位图。
  在 Linux 上，`nlsb` 只在模拟的缓存目录里测过，没有在真实运行的 Linux QQ 上验证。QQ 更新后，这些行为都可能改变。
- 屏蔽替换的只是图片，消息气泡本身还在。
- 手动屏蔽的表情会提前放好占位文件。QQ 下次收到同一表情时会不会直接用这些文件，还没有实测确认；
  如果不会，监听也会在新文件落地后 0.5 秒内把它替换掉，只是可能闪一下原图。
- macOS 上第一次运行时，系统可能会弹窗请求"访问其他 App 的数据"。如果后台服务没有生效，先看 `nlsb.log`。
- 这个工具修改的是第三方应用的缓存，不在 QQ 官方支持的范围内。请自行判断是否使用。

## 开发

```bash
python tests/test_features.py      # 规则识别器的特征行为（只用合成图）
python tests/test_collage.py       # 拼图切分（只用合成图）
python tests/test_gpu.py           # GPU 与 CPU 逐位一致（没有 GPU 时自动跳过）
python tools/review.py             # 在浏览器里检查自动屏蔽的结果，标出误伤和漏网的；--apply 应用标注
python tools/train_head.py labels.csv   # 用自己的标注重新训练分类器（见 docs/model.md）
python tools/tune.py labels.csv    # 用自己的标注调规则识别器的参数
python tools/bench.py <图片目录>    # 规则识别器的性能（会按可用内存自动限制进程数）
```

调试用的环境变量（普通使用不需要）：

| 变量 | 作用 |
|---|---|
| `NLSB_HOME` | 数据目录 |
| `NLSB_QQ_ROOT` | QQ 的数据目录 |
| `NLSB_DETECTOR=rules` | 改用规则识别器（不下载模型） |
| `NAILONG_MODEL_DIR` | 模型存放目录（默认 macOS `~/Library/Caches/nailong-detector`，Linux `~/.cache/nailong-detector`） |
| `HF_ENDPOINT` | 模型下载地址的镜像 |

`nlsb run` 在前台运行服务（后台服务就是这样启动的）。

仓库里**不包含**任何训练或评估用的图片和标注
